# 虚构排序选票可追查计数分析系统

这是一个**只使用虚构候选人与虚构选票**的 STV / 可转移票计数实验室，不连接、不请求、不模拟任何真实选举服务。系统是零前端依赖的静态网页：计数核心使用 ES Module 和 Node 内置测试运行器，浏览器端不需要安装第三方包。

## 启动网页

```bash
npm start
# 或：node server.mjs
# 默认监听 0.0.0.0:4173；只想本机访问可用 HOST=127.0.0.1 PORT=4173 npm start
```

然后打开 <http://127.0.0.1:4173>。

也可以用任意静态服务器托管本目录，例如：

```bash
python3 -m http.server 8000
```

> 直接双击 `index.html` 在部分浏览器下会因为 ES Module 的 `file://` CORS 限制无法加载；请使用上面的静态服务器。

运行测试：

```bash
npm test
```

测试包括精确分数、四个内置样例、60 组随机小规模选举的“批量票批计数 ↔ 逐票解释器”对照、撤票影响和报告校验和复现。

## 网页能做什么

- 在网页中配置：
  - 计数名称、应选席位；
  - 候选人名单（每行一个，支持 `id|名称`）；
  - 排序选票文本和选票处理顺序；
  - 重复候选处理方式；
  - 并列处置规则（人工分支、候选人名单顺序、可复现种子哈希）。
- 逐轮显示：
  - 轮初 / 轮末精确票值；
  - 当选、直接当选、淘汰和并列待裁；
  - 当选余额（surplus）、转移系数和各批流向；
  - 淘汰票的全额转移；
  - 无后续偏好导致的耗尽票；
  - 每轮票值守恒等式。
- 最低票精确并列时可一次保存多个裁决分支：
  - 分支只保存决策映射和父分支；
  - 新分支共享此前不可变轮次前缀；
  - 选择、查看或删除一个分支不会覆盖其他分支的计数。
- 对选票“标记争议”或“撤销 / 恢复”：
  - 撤销时排除该票；
  - 自动对照撤销前后的精确轮次签名，找到最早受影响阶段或轮次；
  - 用同一组分支决策重算后续轮次；若产生新并列，会停下等待新分支裁决。
- “确认并固化报告”会把当时的配置、选票、选票状态、分支决策、完整结果和 SHA-256 存入浏览器 `localStorage`。之后修改当前工作台或撤票，旧报告仍可从快照独立复现校验；也可以在“报告”页导入已导出的报告 / 审计 JSON 重新校验。
- 点击任意候选人按钮，可按流入 / 转出事件追溯到具体原票、原始排序、精确变动金额和源票批保留值。
- 导出：
  - 完整审计 JSON；
  - 逐轮计票 CSV；
  - 票流 / 原票分录 CSV；
  - Markdown 报告；
  - 每份已确认报告还可单独导出 JSON 或归档 Markdown。

## 内置样例与示例导出

网页顶部“载入内置样例”可选择：

1. **三方最低票并列**：第 2 轮 `白岚 / 陈清 / 多瑙` 精确同分；三个裁决产生不同后续，其中裁决多瑙出局后还会出现第二次并列。
2. **重复候选偏好**：例如 `周衡 > 周衡 > 林杉 > 林杉 > 许和`，默认只保留第一次出现。
3. **空白与无有效偏好**：显式空票、`.` 空票和未知候选人票进入耗尽票池。
4. **分数长链转移**：55 张票、5 席、Droop 配额 10；原票 `S001` 连续经过 `1/3 → 2/7 → 3/13 → 1/6 → 1/11`，最终出现精确金额 `1/3003`。

`example-exports/` 中附带由 `npm run export:examples` 生成的真实 JSON / CSV / Markdown 导出样例，可直接检查文件结构和校验和。

## 明确的计数算法：精确分数加权包容 Gregory STV

算法版本：`wig-stv-exact-v1`。

### 1. 数据规范化

- 每张纳入计数的原票初始票值为精确整数 `1`。
- 偏好按 `>`、`→`、逗号、顿号、分号、竖线或制表符分隔。
- 无法匹配候选人的偏好记为未知项并跳过。
- 重复候选人默认只保留第一次出现；也可配置为“出现重复则整张票无有效偏好”。
- 没有任何有效偏好的选票在初始分配时成为耗尽票。
- 已撤销选票不进入计数，但仍保留在输入快照和审计记录中。

### 2. 精确分数与配额

所有票值、余额、比例和守恒量都使用 `js/fractions.js` 中由 `BigInt` 支持的不可变分数：

\[
\frac{a}{b}+\frac{c}{d}=\frac{ad+bc}{bd},\qquad
\frac{a}{b}\frac{c}{d}=\frac{ac}{bd}
\]

比较分数时使用交叉相乘：

\[
\frac{a}{b}<\frac{c}{d}\iff ad<cb
\]

因此不会用浮点数四舍五入判断谁并列、谁淘汰。网页中的小数只是显示提示，不参与任何决策。

有效票值记为 \(V\)（至少有一个有效偏好且未撤销的选票数），席位为 \(S\)。Droop 配额为精确整数：

\[
Q=\left\lfloor\frac{V}{S+1}\right\rfloor+1
\]

### 3. 每轮流程

每轮从当前票批状态计算所有候选人的精确票值，然后按以下顺序处理：

1. **已当选者新增余额**：如果早先当选、名下保留约 \(Q\) 票值的候选人又收到后续转移，使其总票值 \(X>Q\)，先转移其新增余额。
2. **剩余候选人不足剩余席位**：若继续候选人数 \(\le\) 剩余席位数，他们全部不经配额当选，计数完成。
3. **达到配额者当选**：所有票值 \(X\ge Q\) 的继续候选人在同一轮当选。
   - 余额 \(R=X-Q\)；
   - 对该候选人名下每个当前票批应用同一精确比例：
     \[
     \rho=\frac{X-Q}{X}
     \]
   - 票批当前值为 \(w\) 时，转移 \(w\rho\)，源票批保留 \(w(1-\rho)\)；
   - 同一轮同时当选的候选人视为同时移出“继续候选”集合，余额转移沿偏好跳过所有已当选 / 已淘汰者，因此不会依赖同轮处理顺序。
4. **无人达到配额时淘汰最低票者**：
   - 找到继续候选人中的最小精确票值；
   - 若多人精确相等，生成稳定 tie key 和并列事件；
   - 按人工分支、候选人名单顺序或种子哈希选出一人；
   - 淘汰者名下全部票值按比例 `1` 转移。
5. **目标偏好**：从被转移候选人在该原票有效偏好中的位置之后查找，跳过所有非继续状态的候选人；找不到目标时票值耗尽。

系统会一直运行到席位填满，或在人工并列规则下停在 `tie_pending` 状态等待保存分支。即使席位已满，当前轮新当选者的余额转移仍会完整记录，方便审计长分数链和最终流向。

### 4. 票批、流向和原票追溯

计数核心维护 lot / 票批：

- 初始票批来自原票的第一有效偏好；
- 每次部分转移会减少源票批值，并在目标候选人处创建子票批；
- 子票批记录父票批、深度和来源流向；
- 每次转移按目标候选人 / 耗尽票池分组为 flow；
- flow 的 `entries` 保存每张原票的精确变动金额。

因此点击候选人时，可以列出：

- 哪张原票；
- 在哪一轮；
- 因初始分配、余额转移还是淘汰转移；
- 从谁而来 / 向谁而去；
- 变动的精确分数；
- 源票批保留了多少。

### 5. 每轮守恒

设第 \(r\) 轮所有候选人名下票值之和为 \(H_r\)，累计耗尽票值为 \(E_r\)，纳入计数的活跃原票总数为 \(T\)。每轮动作前后都检查：

\[
H_r+E_r=T
\]

若存在已撤销票 \(R\)，还会显示全量审计守恒：

\[
H_r+E_r+R=T+R=N
\]

其中 \(N\) 是载入快照的原票总数。所有比较均为分数精确相等。若不平衡，引擎直接抛错，而不是生成看似成功的报告。

## 并列分支模型

tie key 的形式为：

```text
r<轮次>-elimination-minimum-<排序后的候选人ID>
```

例如：

```text
r2-elimination-minimum-c2_c3_c4
```

分支对象只保存：

```js
{
  id,
  name,
  parentId,
  decisions: {
    [tieKey]: candidateId
  }
}
```

纯函数 `countElectionBatch(input, decisions)` 保证同一输入和同一决策映射产生同一结果。新分支从父分支复制决策映射并增加一个裁决，不会修改父分支或兄弟分支。网页显示新分支与父分支的首个差异轮次，从而给出“共享前 N 轮”的可核查结论。

撤票后轮次号可能前移或后移。重放决策时先精确匹配完整 tie key；若未命中，但决策中存在唯一一条“并列类型 + 排序后候选人集合”相同的旧 key（仅轮次前缀不同），且旧选择仍在新并列集合中，则按该旧裁决重放，并在 UI / Markdown 中标注重放来源。若存在多条互相冲突的同集合历史决策，系统不猜测，仍返回待并列。

## 撤销争议票和最早受影响轮次

撤销选票时，网页会：

1. 用撤销前输入和当前分支决策运行一次精确结果 `before`；
2. 把该票状态改为 `rescinded`，写入原因和状态历史；
3. 用撤销后输入运行 `after`；
4. `findEarliestAffectedRound(before, after)` 比较：
   - 第 0 阶段：配额、有效票值、计票总票值、完成状态；
   - 每轮的精确票型、当选 / 淘汰、tie key / 裁决、守恒值；
   - 每批流向的 from/to、比例、总额和逐原票金额。
5. 返回第一个不同的轮次，后续轮次即为重算结果。

撤销一张有第一偏好的票通常第 1 轮就会变化；如果只更正很靠后的偏好，前若干轮可能完全相同，系统会定位到更晚的首次差异。

## 已确认报告为什么能复现

“确认并固化报告”不是只保存页面上显示的文字，而是保存：

- 原始网页草稿；
- 规范化后的完整输入和全部选票状态；
- 当前分支决策及全部分支摘要；
- 完整精确结果（分数序列化为 `{ "$f": "n/d" }`）；
- 逐票解释器对照摘要；
- 当时的影响分析；
- 结果 SHA-256 `resultChecksum`；
- 整个报告负载的 SHA-256 `auditChecksum`；
- 生成好的 Markdown。

“从快照复现校验”会完全从 `report.input` 和 `report.branch.decisions` 重新运行引擎，重新计算结果哈希，并与旧的 `resultChecksum` 精确比较。当前工作台之后怎么改，都不会影响这份快照。

## 逐票解释器对照

`js/counter.js` 是批量票批 / lot 实现；`js/interpreter.js` 是结构上独立的小规模参考实现：

- 批量引擎操作票批和分组 flow；
- 解释器为每张选票维护 `候选人 → 当前持有分数` 的账户，按配置的唱票顺序逐票处理；
- `js/compare.js` 将两边的配额、当选 / 淘汰、每轮分数、耗尽值、tie 和逐原票流向转成精确签名字段后深度比较。

网页对不超过 240 张活跃票的当前数据自动运行对照；测试中的四个样例和随机样例均强制运行。确认报告要求没有已知对照差异且守恒通过。

## 非目标与边界

- 这是虚构数据的审计 / 教学 / 分析工具，不是真实选举计票系统。
- 未实现多种 STV 变体切换；当前算法口径固定为上面的 `wig-stv-exact-v1`。
- 小数条和小数文本只用于阅读，所有资格、并列、当选和淘汰判断均以精确分数为准。
